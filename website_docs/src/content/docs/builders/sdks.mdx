FrameWorks publishes SDKs for TypeScript, Go, and Python. All three are generated from the public
GraphQL schema and the same operation documents, share one version, and pass the same conformance
fixtures, so they behave the same way. Every example on this page is a file in the repository that
CI compiles or type-checks (`tsc`, `go vet`, `mypy`).

Every public root query, mutation, and subscription that is not deprecated, and every field that
takes arguments, has a generated typed method in each SDK. A namespace root such as `analytics`,
whose data sits behind fields that take arguments, has no method of its own; those fields have
theirs. Fields without arguments nested deeper than a method's default selection are typed only
through the TypeScript [custom selections](#custom-selections); in Go and Python you reach them
with your own GraphQL document. The [GraphQL schema reference](/builders/api-schema/) lists the
method names under each root field.

## Generated operations

Each operation is a typed document in TypeScript (`GetStreamDocument`, passed to
`client.request`), a function in Go (`frameworks.GetStream(ctx, client, id)`), and a method on the
client in Python (`client.get_stream(id=...)`). The operations come from two sources:

- **Default operations.** One per public root field and one per field that takes arguments on a
  type reached from `Query` through single (non-list) objects. A nested operation selects the
  path from the root down to its field and takes every argument on that path as a variable: the
  `streamAnalyticsSummary(streamId:)` field under `analytics.usage.streaming` is
  `GetStreamAnalyticsSummary(streamId, timeRange)`. A field that takes arguments on a type
  reachable only through a list, union, or interface is reached through `node(id:)` when the type
  implements `Node`: `InfrastructureNode.metricsConnection` is
  `GetInfrastructureNodeMetricsConnection(id, page, timeRange)`, which selects
  `node(id:) { ... on InfrastructureNode { metricsConnection } }`.
- **Hand-written operations.** 44 documents with a curated selection (for example `CreateStream`,
  `ListStreams`, `ListPushTargets`). A hand-written operation replaces the default operation of
  the field it addresses.

**Names.** A default query is `Get<Field>` and a default mutation or subscription is `<Field>`,
in PascalCase; Python uses the snake_case form (`get_stream_analytics_summary`). A nested query
is `Get` plus its field, or `Get` plus every field on its path when another query ends in a field
of the same name (`GetAnalyticsInfraServiceInstancesHealth`). A query through `node(id:)` is `Get`
plus the type and the field (`GetInfrastructureNodeMetricsConnection`). A name equal to a schema type gets
the operation kind as suffix (`CryptoTopupStatusMutation`). Go subscriptions are
`Subscribe<Operation>`.

**Default selection.** A default operation selects the returned type's scalar and enum fields
and its argument-free object, union, and interface fields to depth 2. Connections select
`edges { cursor node }`, `pageInfo`, and `totalCount`. Unions and interfaces select `__typename`
and each member's fields. Fields that take arguments are never part of a selection; they have
operations of their own. For anything deeper, see [Custom selections](#custom-selections).

## Runtime

Around the operations, each SDK has the same small runtime:

- **Authentication.** Pass a developer token, or a function that returns the current one. The
  client reads it for every request, and a subscription reads it again for every reconnect.
- **Retries.** Queries are retried on network errors and HTTP 408, 429, 500, 502, 503, and 504,
  with backoff and `Retry-After`. A mutation is retried only when the request provably never
  reached the server: the connection was refused, the host name did not resolve, or the gateway
  answered 429. A mutation that timed out, lost its connection after sending, or got a 5xx may
  have run, and the gateway does not deduplicate replayed mutations, so the client returns the
  error instead; check the outcome before you send it again. Paid mutations settled with x402
  need an idempotency key, and the gateway deduplicates those by it.
- **Subscriptions.** A connection the gateway closes with 4403 before acknowledging it has an
  invalid or expired token and fails with `AuthenticationError`. Any other close or network error,
  before or after the acknowledgement, reconnects with backoff; each acknowledged connection
  starts the reconnect budget again.
- **Typed errors.** Every failure is a subclass of `FrameWorksError` with the same name in each
  language: `NetworkError`, `AuthenticationError`, `PaymentRequiredError`, `RateLimitError`,
  `ServerError`, `HTTPError`, `ProtocolError`, `GraphQLError`, `SchemaMismatchError`,
  `ResultError`, `ServerTooOldError`, `UnsupportedOperationError`, and `UploadError`.
- **Partial results.** A response whose errors all sit below a root field that came back (a
  nullable field the server set to `null`, such as `Stream.metrics` for a token without
  `analytics:read`) returns its data, and the errors go to a handler: `onPartialErrors` on the
  client or per request in TypeScript, `ClientOptions.OnPartialErrors` or
  `frameworks.WithPartialErrors(ctx, fn)` in Go, and `on_partial_errors=` on the client or per
  call in Python. `UNAUTHORIZED`, `RATE_LIMITED`, document errors, errors without a path, and
  errors that null a root field still fail the call. See
  [Partial results](/builders/api-reference#partial-results).
- **Scopes.** The stream operations (`ListStreams`, `GetStream`, `CreateStream`, `UpdateStream`,
  `RefreshStreamKey`) need only `streams:read` and `streams:write`. Live state is in
  `GetStreamMetrics` and `ListStreamMetrics`, which need `analytics:read`. See
  [Token scopes](/builders/api-reference#token-scopes).
- **Result unions.** Most mutations return a union of the result and typed errors.
  `expectResult` returns the result or raises a `ResultError` naming the error member, its
  message, and the input field or resource it concerns.
- **Pagination.** Iterators for the three list shapes: relay cursors (`streamsConnection`),
  offsets (`storageArtifactsConnection`), and page tokens (`dvrChapters`).
- **Server check.** Before operations the client reads `serverInfo`, shared per URL and read again
  after five minutes. See [Versions](#versions).

## Subscribe to events

`tenantEvents` delivers the same events as webhooks over a WebSocket. When the gateway closes the
connection before acknowledging it, the token is invalid or expired: the SDK raises
`AuthenticationError` and does not reconnect. After any other drop it reconnects, reading the
token again.

Every public subscription is generated the same way, with the same connection handling: in
TypeScript, pass its document (`LiveStreamEventsDocument`) to the subscription client's
`subscribe`, which yields the document's result type; in Go, call `Subscribe<Operation>`
(`SubscribeLiveStreamEvents`), which returns an `iter.Seq2` of the operation's response type; in
Python, iterate the async client's method (`live_stream_events`). The sync Python client has no
subscriptions, because ariadne-codegen generates them only for an async client.

## Custom selections

Every generated operation has a default selection. For fields beyond it:

- **TypeScript** has typed selections over the whole public schema in
  `@livepeer-frameworks/api/select`, generated with [Genql](https://genql.dev). `createSelectClient`
  wraps a client (and optionally a subscription client), so a selection runs with the same
  authentication, retries, typed errors, and server check as a generated document. `__args` passes
  arguments, `on_<Type>` selects a union member or interface implementation, and a selected field
  the schema does not have throws before anything is sent. The entry holds the schema's type map
  (about 20 kB gzipped); the main entry does not load it. `client.request` also accepts a document
  string, with an untyped result.
- **Go** takes your own genqlient documents written against
  [`schema.public.graphql`](https://github.com/Livepeer-FrameWorks/monorepo/blob/master/pkg/graphql/public/schema.public.graphql):
  `*frameworks.Client` implements genqlient's `graphql.Client`, and `MakeRequest` sends any query or
  mutation through the SDK runtime.
- **Python** has no typed builder. ariadne-codegen's custom operation builder covers only queries
  and mutations and returns untyped dictionaries with undecoded scalars, so send your own document
  through `execute` (or `execute_ws` on the async client for subscriptions).

Give a custom operation a name of your own: the server check looks up an SDK operation's release by
its name.

## Versions

The SDKs are 0.x until the platform reaches 1.0, and the three languages always share a version.
Under 0.x each minor version is a line: 0.1, 0.2, and so on. A line names the oldest FrameWorks
release it supports and supports every stable release from there on.

| SDK line | Oldest supported FrameWorks release | Operations                                       |
| -------- | ----------------------------------- | ------------------------------------------------ |
| 0.3      | v0.3.11                             | 182 default and 45 hand-written operations (227) |

Lines 0.1 and 0.2 (the 44 hand-written operations) are retired; use 0.3.

Within a line, operations are only added; a breaking change starts a new minor line. The public
schema follows the same rule from FrameWorks v0.3.11 on: a field, argument, enum value, or union
member a client can use is deprecated before it is removed, and removed only after every supported
line's oldest release has it deprecated. A field marked **Experimental** in the schema reference is
exempt until the release its badge names. Before the first operation, the client reads the
server's `serverInfo`:

- A stable release older than the line's minimum raises `ServerTooOldError`.
- An operation added after the server's release raises `UnsupportedOperationError` and is not
  sent.
- Development builds and release candidates are not checked.
- If the check itself fails, for example on a network error, the call goes ahead and the next
  call checks again. A v0.3.10 gateway answers an anonymous `serverInfo` with HTTP 402; that is no
  verdict either, and the client does not ask that gateway again for five minutes.
- The answer is reused for five minutes. The client asks again at once before a cached answer
  would fail a call as too old, and when an operation fails schema validation; if the fresh answer
  fails the check, the call fails with that error instead.

<Aside type="note" title="New enum values and union members">
  A newer server can return an enum value or union member the SDK does not know. Every SDK decodes
  the response anyway, so keep a default branch wherever you branch on an enum or on `__typename`:

- **Union members.** TypeScript returns the member's object as sent. Go decodes it as
  `*frameworks.UnknownMember` and Python as `UnknownMember`, each carrying the `__typename` and
  the member's raw JSON. The TypeScript union types list only the members the SDK knows.
- **Enum values.** TypeScript enum types include `"%future added value"`. Go enums are string
  types, so an unknown value keeps its string. Python enums subclass `OpenEnum`: an unknown value
  decodes to a member whose `value` is the server's string and whose `is_unknown` is true.
- **Errors.** `expectResult` raises an unknown member as a `ResultError` carrying its
  `__typename`, message, and code.

Webhook parsing returns an event type the SDK does not know as a raw event.

</Aside>
