The compositor enables multi-source layout control — arrange cameras, screen share, and media files into layouts with scenes and layers, and put logos and text above them. It runs in the browser.

<Aside type="tip" title="On by Default in the Drop-in Components">
  The React, Svelte, and Web Component drop-in components enable the compositor by default. It works
  with a single source (fullscreen solo layout). The layout does not change when you add sources: a
  new source starts full-frame on top until you pick a layout in the compositor controls or call
  `applyLayout()`. The vanilla `createStreamCrafter()` facade and the headless controllers leave it
  off until you call `enableCompositor()`.
</Aside>

## Enabling and Disabling the Compositor

In the drop-in components, disable it if you need raw source streaming without compositing
overhead:

**React:**

```tsx
<StreamCrafter whipUrl="..." enableCompositor={false} />
```

**Svelte:**

```svelte
<StreamCrafter whipUrl="..." enableCompositor={false} />
```

**Web Components:**

```html
<!-- Disable via JS property -->
<fw-streamcrafter id="studio" whip-url="..."></fw-streamcrafter>
<script>
  document.getElementById("studio").enableCompositor = false;
</script>
```

**Vanilla:** the compositor is off by default. Enable it with a method call, and optionally pass
compositor settings:

```ts
const studio = createStreamCrafter({ whipUrl: "..." });

await studio.enableCompositor({ width: 1920, height: 1080, frameRate: 30 });

// Later, return to raw source streaming
studio.disableCompositor();
```

## Layout Modes

The compositor ships with 17 built-in layout presets:

| Mode          | Label              | Min Sources | Description                       |
| ------------- | ------------------ | ----------- | --------------------------------- |
| `solo`        | Solo               | 1           | Single source fullscreen          |
| `pip-br`      | PiP (bottom-right) | 2           | Main + small overlay bottom-right |
| `pip-bl`      | PiP (bottom-left)  | 2           | Main + small overlay bottom-left  |
| `pip-tr`      | PiP (top-right)    | 2           | Main + small overlay top-right    |
| `pip-tl`      | PiP (top-left)     | 2           | Main + small overlay top-left     |
| `split-h`     | Split Horizontal   | 2           | Side-by-side split                |
| `split-v`     | Split Vertical     | 2           | Top/bottom split                  |
| `focus-l`     | Focus Left         | 2           | Large left, small right           |
| `focus-r`     | Focus Right        | 2           | Small left, large right           |
| `pip-dual-br` | Main + 2 PiP       | 3           | Main with two small overlays      |
| `pip-dual-bl` | Main + 2 PiP Left  | 3           | Main with two small left overlays |
| `split-pip-l` | Split + PiP Left   | 3           | Side-by-side with left overlay    |
| `split-pip-r` | Split + PiP Right  | 3           | Side-by-side with right overlay   |
| `featured`    | Featured           | 3           | Large center, small sides         |
| `featured-r`  | Featured Right     | 3           | Large right, small left stack     |
| `grid`        | Grid               | 2+          | Equal-size grid                   |
| `stack`       | Stack              | 2+          | Vertical stack                    |

### Applying Layouts

**React (via hook):**

```tsx
const crafter = useStreamCrafterV2({ whipUrl: "..." });
const compositor = useCompositor({
  controller: crafter.getController(),
  autoEnable: true,
});

compositor.applyLayout({ mode: "pip-br", scalingMode: "letterbox", pipScale: 0.25 });
```

**Vanilla:**

```ts
studio.sceneManager?.applyLayout({
  mode: "split-h",
  scalingMode: "crop",
});
```

**Web Components:**

```js
studio.pc
  .getController()
  ?.getSceneManager()
  ?.applyLayout({ mode: "grid", scalingMode: "letterbox" });
```

### Cycling Source Order

In the built-in compositor controls, clicking the active layout again cycles the source order: the
first source moves to the back. Hold Shift to cycle backward.

Calling `applyLayout()` again with the same layout does not cycle. Call `cycleSourceOrder()`
instead:

```ts
// React useCompositor hook or Svelte createCompositorStore
compositor.cycleSourceOrder(); // forward
compositor.cycleSourceOrder("backward");

// Core SceneManager
studio.sceneManager?.cycleSourceOrder("forward");
```

## Scaling Modes

Each layout supports three scaling modes that control how sources fill their allocated space:

| Mode        | Description                                                    |
| ----------- | -------------------------------------------------------------- |
| `letterbox` | Fit entire source, add black bars if aspect ratios don't match |
| `crop`      | Fill the space completely, cropping edges if needed            |
| `stretch`   | Stretch to fill exactly, ignoring aspect ratio                 |

## Scenes

Scenes are named collections of layers. Switch between scenes for different broadcast segments. A scene has no layout of its own: the compositor keeps one current layout, and `applyLayout()` arranges the active scene's layers with it.

```ts
// React useCompositor hook or Svelte createCompositorStore
const interview = compositor.createScene("interview");
const soloCam = compositor.createScene("solo-cam");

if (interview) {
  compositor.setActiveScene(interview.id);
}
```

When you work directly with the core `SceneManager`, use the returned scene ID for later calls:

```ts
const sceneManager = studio.sceneManager;

// Create a scene
const interview = sceneManager?.createScene("interview");
sceneManager?.createScene("solo-cam");

// Switch to a scene
if (interview) {
  sceneManager?.setActiveScene(interview.id);
}
```

### Scene Transitions

`transitionTo()` accepts the `cut`, `fade`, `slide-left`, `slide-right`, `slide-up`, and `slide-down`
types with a duration and easing.

## Layers

A new source becomes a layer in the active scene only. To show it in another scene, call
`addLayer(sceneId, sourceId)` for that scene. Each layer has independent controls:

| Property            | Type      | Description                   |
| ------------------- | --------- | ----------------------------- |
| `id`                | `string`  | Layer identifier              |
| `sourceId`          | `string`  | Linked media source           |
| `visible`           | `boolean` | Show/hide layer               |
| `zIndex`            | `number`  | Stack order (higher = on top) |
| `transform.opacity` | `number`  | Layer opacity (0-1)           |

### Layer Operations

```ts
// React useCompositor hook. With the Svelte store, read $compositor.activeSceneId instead.
const sceneId = compositor.activeSceneId;
if (!sceneId) return;

// Toggle visibility
compositor.setLayerVisibility(sceneId, layerId, false);

// Change opacity
compositor.updateLayerTransform(sceneId, layerId, { opacity: 0.7 });

// Reorder layers by layer ID, bottom to top
compositor.reorderLayers(sceneId, ["layer-1", "layer-2", "layer-3"]);

// Remove a layer
compositor.removeLayer(sceneId, layerId);
```

## More Than One Camera

`getCameraChoices()` lists the video inputs, and `startCamera({ videoDeviceId })` adds one as another
source. The drop-in components use both behind **Add Camera**. The list is empty until the browser
has shown device IDs, which it does once camera permission is granted.

```ts
const choices = await studio.getCameraChoices();
const next = choices.find((choice) => !choice.inUse);
if (next) await studio.startCamera({ videoDeviceId: next.deviceId });
```

The first camera opens the microphone. Later cameras are video only unless you pass `audio: true`,
so one microphone does not reach the mix twice.

## Overlays

An overlay is a layer that stays above the sources at its own position. Layouts, source cycling, and
sources added later leave it where it is. The compositor components and hooks add overlays to the
active scene; `SceneManager` takes a scene ID.

```ts
// A picked file is decoded in the browser and never uploaded.
const { sourceId: logo } = await sceneManager.addImageOverlay(sceneId, file);

// Text is drawn at its size in output pixels, on a band sized to the text.
const { sourceId: lowerThird } = sceneManager.addTextOverlay(sceneId, {
  text: "Ada Lovelace",
  fontSize: 48,
  color: "#ffffff",
});

// Editing redraws the overlay at once and keeps its position.
sceneManager.updateTextOverlay(lowerThird, { text: "Ada Lovelace, Analyst" });

// x and y run from 0 to 1 across the room the overlay leaves in the frame,
// so 1 is flush with the right or bottom edge at any size.
// size is the width of an image as a fraction of the frame.
sceneManager.setOverlayPlacement(logo, { x: 1, y: 0, size: 0.2 });

sceneManager.removeOverlay(logo);
```

`getOverlays(sceneId)` returns the overlays of a scene with their placement and text. The hook and
store expose it as `overlays` for the active scene. PNG transparency and SVG files are supported.

## Media Files

`addMediaFile(file, { loop })` plays a local video or audio file as a source. Its video goes through
the compositor and its audio through the mixer, with the same volume and mute controls as any other
source. An audio file has no layer.

```ts
const source = await studio.addMediaFile(file, { loop: true });

studio.pauseMediaSource(source.id);
studio.playMediaSource(source.id);
studio.setMediaSourceLoop(source.id, false);
```

`source.media` holds the playback state. A file that runs out without looping stays in the mix on
its last frame, and playing it again starts it over.

<Aside type="note" title="The file plays from the tab">
  The file is read by this browser tab and never uploaded, so the tab must stay open while the file
  is in the mix. A browser that cannot capture from a media element refuses the file with an error.
</Aside>

## Saving and Restoring the Layout

A studio layout is plain JSON data: the scenes with their names and background colors, the active
scene, the image and text overlays with their positions and the scenes that show them, and the
layout preset. It holds no camera, screen or media-file layers, because those belong to one
session's captures. Sources added after a layout is applied join the active scene and the preset
places them. An image picked from disk is carried as a data URL, stored at no more than the
frame size, so the layout stays small enough for page storage.

The drop-in components take the stream a layout belongs to and the layout to start from, and
report changes:

| Prop / property  | Type                                                             | Description                                                                                                       |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `layoutKey`      | `string`                                                         | The stream (or anything else) the layout belongs to; `layout-key` attribute on `<fw-streamcrafter>`               |
| `initialLayout`  | `StudioLayout \| null`                                           | Layout for `layoutKey`, applied when the compositor starts or the key changes                                     |
| `onLayoutChange` | `(layout: StudioLayout, layoutKey: string \| undefined) => void` | Called about 300 ms after the scenes, overlays, active scene or layout preset change, with the key they belong to |

`<fw-streamcrafter>` takes them as JS properties and also dispatches a `fw-sc-layout-change` event
with `event.detail.layout` and `event.detail.layoutKey`. Save each layout under the key it comes
with: a report for a key the studio has already left is dropped, so a late report never lands on
the next stream.

**React:**

```tsx
function readLayout(streamId: string): StudioLayout | null {
  try {
    return JSON.parse(localStorage.getItem(`studio-layout:${streamId}`) ?? "null");
  } catch {
    return null;
  }
}

<StreamCrafter
  whipUrl={whipUrl}
  layoutKey={streamId}
  initialLayout={readLayout(streamId)}
  onLayoutChange={(layout, key) => {
    if (key) localStorage.setItem(`studio-layout:${key}`, JSON.stringify(layout));
  }}
/>;
```

**Svelte:**

```svelte
<StreamCrafter
  {whipUrl}
  layoutKey={streamId}
  initialLayout={readLayout(streamId)}
  onLayoutChange={(layout, key) => {
    if (key) localStorage.setItem(`studio-layout:${key}`, JSON.stringify(layout));
  }}
/>
```

**Web Components:**

```html
<fw-streamcrafter id="studio"></fw-streamcrafter>
<script>
  const studio = document.getElementById("studio");
  function showStream(streamId, whipUrl) {
    studio.whipUrl = whipUrl;
    studio.layoutKey = streamId;
    studio.initialLayout = JSON.parse(localStorage.getItem(`studio-layout:${streamId}`) ?? "null");
  }
  studio.addEventListener("fw-sc-layout-change", (e) => {
    const { layout, layoutKey } = e.detail;
    if (layoutKey) localStorage.setItem(`studio-layout:${layoutKey}`, JSON.stringify(layout));
  });
</script>
```

Wrap the `localStorage` calls in `try`/`catch` in a real page: storage can be blocked, and a
layout holding a picked image can be larger than the quota.

To switch streams, change `whipUrl`, `layoutKey` and `initialLayout` together. The running studio
keeps its camera, screen and media sources and shows the new key's `initialLayout`, or the default
layout when it is `null` or does not apply. The next broadcast goes to the new `whipUrl`; a
broadcast that is live when `whipUrl` changes is stopped. With the vanilla studio, switch in place
with `studio.setWhipUrl(url)` and `studio.importLayout(saved ?? createDefaultStudioLayout())`;
`createDefaultStudioLayout` comes from `@livepeer-frameworks/streamcrafter-core`.

For the same `layoutKey`, the compositor keeps its own layout: when it is turned off and on again,
and when the studio builds a new controller for a new quality profile or `debug` setting.
`initialLayout` is read only when the compositor starts or the key changes, so a new object for the
same key changes nothing. A stored layout that does not apply when the compositor starts is logged
and skipped; it never keeps the compositor off.

You can also read and apply a layout directly. `exportLayout()` returns the layout; while the
compositor is off it returns the layout from when it was last on, and `null` when it never ran.
`importLayout(layout)` replaces the scenes and overlays and needs the compositor to be on. It
checks the layout and decodes its images first, so a layout that fails leaves the studio as it was.

| Binding     | Where                                                           |
| ----------- | --------------------------------------------------------------- |
| React       | `exportLayout` and `importLayout` on the `useCompositor` result |
| Svelte      | `exportLayout` and `importLayout` on the compositor store       |
| Web Element | `studio.exportLayout()` and `studio.importLayout(layout)`       |
| Vanilla     | `studio.exportLayout()` and `studio.importLayout(layout)`       |

Layouts from storage or another page can be checked before use with `parseStudioLayout(value)` from
`@livepeer-frameworks/streamcrafter-core`. It returns the layout or throws with the first problem,
such as an unsupported `version` or an unknown layout mode.

## Renderer

The compositor automatically selects the best available renderer:

| Renderer   | Requirements | Performance                          |
| ---------- | ------------ | ------------------------------------ |
| `webgpu`   | WebGPU API   | Best — GPU-accelerated compositing   |
| `webgl`    | WebGL 2      | Good — hardware-accelerated fallback |
| `canvas2d` | Canvas API   | Baseline — software rendering        |

The active renderer type and FPS are shown in the compositor controls overlay.

Each framework provides compositor UI components:

```tsx
import {
```

**Svelte:**

```svelte
  } from "@livepeer-frameworks/streamcrafter-svelte";
</script>
```

**Web Components:**

`<fw-streamcrafter>` renders its own compositor overlay. The standalone `<fw-sc-compositor>`,
`<fw-sc-scene-switcher>`, and `<fw-sc-layer-list>` elements are presentational: they do not
connect to a `<fw-streamcrafter>` on their own, so you set their data through JS properties and
handle their events or callbacks. See
[Presentational Sub-Components](/builders/ingest-wc/#presentational-sub-components) for the wiring.

The compositor overlay shows layout icons and scaling mode buttons. Click a layout icon to apply it; click the active layout to cycle source order.
