GraphQL API for stream management, key rotation, analytics, and all platform operations.

<Aside type="note" title="Same schema everywhere">
  Managed and self-hosted deployments run the same Bridge (API Gateway) and GraphQL schema. Some
  fields may return null or errors if the backing service isn’t deployed.
</Aside>

## GraphQL Endpoint

All API interactions are performed through a single GraphQL endpoint. This allows you to fetch exactly the data you need in a single request.

```
%GATEWAY_URL%/graphql
```

Subscriptions use WebSocket:

```
%GATEWAY_WS_URL%
```

All operations go through this single endpoint. Queries read data, mutations change it.

## Authentication

Most requests need a token in the Authorization header:

```
Authorization: Bearer YOUR_JWT_OR_API_TOKEN
```

Get your API token from **Developer → Credentials** in the dashboard.

The dashboard may authenticate via httpOnly cookies.  
Public allowlist (no auth required): the queries `serverInfo`, `resolveViewerEndpoint`, `resolveIngestEndpoint`, `networkStatus`, and the orchestrator queries, plus the mutations `bootstrapEdge` and `walletLogin`, which each carry their own per-call credential in the input.

Subscriptions send the token in the `connection_init` payload of the WebSocket connection:

```json
{ "type": "connection_init", "payload": { "Authorization": "Bearer YOUR_JWT_OR_API_TOKEN" } }
```

A connection without an `Authorization` value is anonymous and can only run public operations. A
connection whose `Authorization` value does not authenticate (expired, revoked, or malformed) is
closed with code `4403` before the server acknowledges it; reconnecting with the same token fails
the same way, so get a new token first. This holds even when the browser also sends a valid session
cookie: a present `Authorization` value is never replaced by another credential. When the gateway
cannot check the token because its authentication service is unavailable, it closes with `1013`
(try again later); reconnect with backoff. Over HTTP the same case answers `503`.

The [SDKs](/builders/sdks) for TypeScript, Go, and Python handle both, and read the token again
for every reconnect.

## Common Usage Patterns

Here are the most frequent operations you'll likely need when building your integration.

### List Your Streams

```graphql
query {
  streamsConnection(page: { first: 20 }) {
    edges {
      node {
        id
        name
        playbackId
        createdAt
        metrics {
          status
          currentViewers
        }
      }
    }
  }
}
```

### Create a Stream

`createStream` creates a push-input live stream for RTMP/E-RTMP, SRT, or WHIP ingest.
Most mutations return a **union** result. Always check `__typename`.

```graphql
mutation {
  createStream(input: { name: "My New Stream" }) {
    __typename
    ... on Stream {
      id
      name
      streamKey
      playbackId
    }
    ... on ValidationError {
      message
      field
    }
    ... on AuthError {
      message
    }
  }
}
```

The returned `streamKey` is secret and is used only for ingest. The returned `playbackId` is the
public viewer identifier used by `/play` URLs and the FrameWorks Player.

For pull-input streams, set `ingestMode: PULL` and provide `pullSource.sourceUri` in
`CreateStreamInput`; see [Pull-input Streams](/builders/pull-streams).

### Get Stream Details

```graphql
query {
  stream(id: "stream-global-id") {
    id
    name
    streamKey
    playbackId
    record
    metrics {
      status
      currentViewers
      isLive
      updatedAt
    }
  }
}
```

### Create a Stream Key

```graphql
mutation {
  createStreamKey(streamId: "stream-global-id", input: { name: "OBS Key" }) {
    __typename
    ... on StreamKey {
      id
      keyValue
      keyName
      createdAt
    }
    ... on ValidationError {
      message
      field
    }
    ... on AuthError {
      message
    }
  }
}
```

### Get Stream Analytics

Most analytics queries take an optional `timeRange`; it is required on `usageAggregates` and `streamAnalyticsSummariesConnection` (and on the federation event, federation summary, and orchestrator performance series queries). Data is returned in aggregated form to help you visualize viewer engagement and usage.

```graphql
query {
  analytics {
    usage {
      streaming {
        streamAnalyticsDailyConnection(
          streamId: "stream-global-id"
          timeRange: { start: "2024-01-01T00:00:00Z", end: "2024-01-07T00:00:00Z" }
          page: { first: 30 }
        ) {
          edges {
            node {
              day
              totalViews
              uniqueViewers
              egressBytes
            }
          }
        }
      }
    }
  }
}
```

Note: analytics `streamId` filters use the Stream global ID (`Stream.id`). Responses return Relay IDs; use `Stream.streamId` for the public UUID used outside GraphQL.

## Playback Resolution

When building a custom player, use the `resolveViewerEndpoint` query. This ensures your viewers are routed to the geographically closest and healthiest edge node.

```graphql
query {
  resolveViewerEndpoint(contentId: "a1b2c3d4e5f6g7h8") {
    primary {
      nodeId
      baseUrl
      protocol
      url
      geoDistance
      loadScore
      outputs
    }
    fallbacks {
      nodeId
      baseUrl
      protocol
      url
    }
    metadata {
      status
      isLive
      viewers
      title
      description
      contentId
      contentType
    }
  }
}
```

Returns a primary endpoint (optimal for the viewer's location) plus fallbacks. Use the primary endpoint first, fall back to others if it fails.

`contentId` is a **playbackId** for live streams, VOD uploads, clips, and DVR recordings (not the raw hash).

If the gateway can’t determine a viewer IP for GeoIP routing, the query still resolves: node selection falls back to scoring without the geographic component.

## Error Handling

A request can fail in three places, and each has its own shape.

**Before GraphQL runs**, the gateway answers with an HTTP status and a JSON body that has `error`,
often `message` and `code`, and no `errors` array:

| Status | Meaning                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------ |
| 401    | The token is invalid, expired, or revoked, or a payment header arrived without a credential.                       |
| 402    | No credential on a non-public operation (with its x402 challenge), or the tenant needs credit or a payment method. |
| 429    | Rate limited. `Retry-After` gives the seconds to wait.                                                             |
| 5xx    | The gateway or a service behind it failed. Queries are safe to retry.                                              |

**While GraphQL runs**, errors come in the `errors` array with `extensions.code`:

```json
{
  "data": { "stream": null },
  "errors": [
    {
      "message": "resource not found",
      "path": ["stream"],
      "extensions": {
        "code": "NOT_FOUND"
      }
    }
  ]
}
```

| `extensions.code`                                   | Meaning                                                          |
| --------------------------------------------------- | ---------------------------------------------------------------- |
| `UNAUTHORIZED`                                      | Missing or invalid credentials.                                  |
| `FORBIDDEN`                                         | The token lacks the permission the operation needs.              |
| `NOT_FOUND`                                         | The resource does not exist or belongs to another tenant.        |
| `VALIDATION_ERROR`                                  | An argument is invalid.                                          |
| `CONFLICT`                                          | The resource already exists, or a concurrent change won.         |
| `FAILED_PRECONDITION`                               | The resource is not in a state that allows the operation.        |
| `RATE_LIMITED`                                      | A service-side limit was reached.                                |
| `UNAVAILABLE`                                       | A service behind the gateway is unavailable or timed out; retry. |
| `INTERNAL_ERROR`                                    | An unexpected failure.                                           |
| `GRAPHQL_VALIDATION_FAILED`, `GRAPHQL_PARSE_FAILED` | The document does not match this server's schema (HTTP 422).     |

Some errors carry a more specific code, for example `BILLING_PROFILE_REQUIRED` with the missing
fields in `extensions.required_fields`. Errors without a code are resolver messages, such as a
missing required input.

**As a result value**, most mutations return a union of the result and typed errors. Select
`__typename` and each error member; a `ValidationError` names the `field`, a `NotFoundError` the
`resourceType` and `resourceId`, and a `RateLimitError` the seconds in `retryAfter`:

```graphql
mutation {
  createStream(input: { name: "" }) {
    __typename
    ... on Stream {
      id
    }
    ... on ValidationError {
      message
      field
    }
    ... on AuthError {
      message
    }
  }
}
```

The [SDKs](/builders/sdks) turn each of these into one typed error class, the same in every
language.

## Building Queries

The fastest way to build queries for your integration:

1. **API Explorer** — Go to **Developer → Playground** in the dashboard. The built-in GraphQL explorer has full schema docs, autocompletion, and lets you run queries against your account. Copy working queries directly into your code.
2. **Ask Skipper** — Tell Skipper what you want to do (e.g. "create a stream from Python" or "list my clips with curl") and it will generate a working snippet in your language, using the live schema.

Both tools stay in sync with the actual schema, so the queries they produce always work.

### Quick Reference

The examples below show the general pattern for calling the API from common languages. For the exact query fields you need, use the API Explorer or ask Skipper.

**curl:**

```bash
curl -X POST %GATEWAY_URL%/graphql \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"query": "{ streamsConnection(page: { first: 5 }) { edges { node { id name playbackId } } } }"}'
```

**JavaScript** (using `graphql-request`):

```javascript
import { GraphQLClient, gql } from "graphql-request";

const client = new GraphQLClient("%GATEWAY_URL%/graphql", {
  headers: { Authorization: "Bearer YOUR_TOKEN" },
});

const data = await client.request(gql`
  query {
    streamsConnection(page: { first: 5 }) {
      edges {
        node {
          id
          name
          playbackId
        }
      }
    }
  }
`);
```

**Python** (using `httpx` or `requests`):

```python
import httpx

resp = httpx.post(
    "%GATEWAY_URL%/graphql",
    headers={"Authorization": "Bearer YOUR_TOKEN"},
    json={"query": "{ streamsConnection(page: { first: 5 }) { edges { node { id name playbackId } } } }"},
)
print(resp.json()["data"])
```

**Go:**

```go
body, _ := json.Marshal(map[string]string{
    "query": `{ streamsConnection(page: { first: 5 }) { edges { node { id name playbackId } } } }`,
})
req, _ := http.NewRequest("POST", "%GATEWAY_URL%/graphql", bytes.NewReader(body))
req.Header.Set("Content-Type", "application/json")
req.Header.Set("Authorization", "Bearer YOUR_TOKEN")
resp, _ := http.DefaultClient.Do(req)
```

For TypeScript, Go, and Python, the [SDKs](/builders/sdks) ship a generated typed operation for
every public root field that is not deprecated and every argument-taking field below `Query`. For
other languages, use any GraphQL client or generate typed bindings from the
[public schema](https://github.com/Livepeer-FrameWorks/monorepo/blob/master/pkg/graphql/public/schema.public.graphql).

## Schema Reference

Browse the [generated GraphQL schema reference](/builders/api-schema/) for public entry points,
arguments, return types, descriptions, and deprecations. It has one page per domain (for example
[Streams](/builders/api-schema/streams/), [Media and storage](/builders/api-schema/media/), and
[Analytics](/builders/api-schema/analytics/)) plus a [Shared types](/builders/api-schema/shared/)
page, and lists the SDK operation names for each root field. Operator-only and service-token-only
entry points are excluded.

The live schema is also available via introspection:

```graphql
{
  __schema {
    types {
      name
      description
    }
  }
}
```

Or use the dashboard's **API Explorer** (Developer → Playground) which shows docs inline.
