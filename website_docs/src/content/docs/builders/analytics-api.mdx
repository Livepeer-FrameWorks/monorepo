The webapp's `/analytics`, `/analytics/audience`, `/analytics/usage`, and `/streams/:id/analytics` pages are all built on the same GraphQL surface you can query directly. This page maps each view to the operations that drive it so you can replicate or extend them in your own dashboards.

<Aside type="note">
  All analytics queries are tenant-scoped via the JWT — you don't need to pass a tenant ID, and you
  can't query across tenants. Bounded time ranges and pagination are enforced server-side; see field
  definitions in the [GraphQL playground](%APP_URL%/developer/playground).
</Aside>

<Aside type="note" title="Cluster data is scoped by intent">
  Stream, audience, routing, QoE, and billing analytics show your tenant's own data, including when
  your streams are routed through a subscribed marketplace/shared cluster. Private node inventory,
  service metrics, enrollment tokens, and cluster inspection are cluster-operator surfaces and
  require ownership of the cluster. Public network maps expose official platform topology, and
  authenticated tenants also see subscribed or owned clusters with basic cluster-level KPIs.
</Aside>

<Aside type="note" title="Player QoE is shipping incrementally">
  Stream health, routing, geographic, usage, and client QoE summaries are available today. The
  FrameWorks npm player also reports view-level QoE as an opt-in beacon: startup time-to-first-frame
  and manifest/segment Resource Timing (`analytics.health.playerBootSummary`), plus
  viewer-experienced rebuffering, frame drops, bitrate/rendition switches, exit-before-start, and
  per-asset VOD retention (`analytics.health.sessionQoeSummary` and
  `analytics.health.vodRetention`). Still maturing: QoE from non-npm / third-party players. See
  [View-Level QoE Analytics](/roadmap#view-level-qoe-analytics).
</Aside>

## Per-stream analytics

The `/streams/:id/analytics` and `/streams/:id/health` views read the `analytics` root: `analytics.health` for health rollups and `analytics.usage.streaming` for viewer, delivery, and quality-tier summaries over a time range.

```graphql
query StreamAnalytics($streamId: ID!, $timeRange: TimeRangeInput) {
  analytics {
    health {
      streamHealthSummary(streamId: $streamId, timeRange: $timeRange) {
        avgBitrate
        avgFps
        avgBufferHealth
        totalRebufferCount
        hasActiveIssues
        currentQualityTier
      }
    }
    usage {
      streaming {
        streamAnalyticsSummary(streamId: $streamId, timeRange: $timeRange) {
          rangeAvgViewers
          rangePeakConcurrentViewers
          rangeUniqueViewers
          rangeViewerHours
          rangeEgressGb
          rangePacketLossRate
          rangeQuality {
            tier1080pMinutes
            tier720pMinutes
            tier480pMinutes
            tierSdMinutes
          }
        }
      }
    }
  }
}
```

For real-time updates, subscribe instead of polling. `liveStreamEvents` carries lifecycle changes with a metrics snapshot; `liveViewerMetrics` emits per-viewer connect and disconnect records with bandwidth and packet counters.

```graphql
subscription LiveStream($streamId: ID) {
  liveStreamEvents(streamId: $streamId) {
    type
    status
    timestamp
    qualityTier
    primaryBitrate
    primaryFps
    totalViewers
  }
}

subscription LiveViewers($streamId: ID!) {
  liveViewerMetrics(streamId: $streamId) {
    timestamp
    action
    protocol
    bandwidthOutBps
    packetsLost
    clientCountry
  }
}
```

## Tenant-wide audience

`/analytics/audience` aggregates viewer counts, geographic distribution, and per-stream rankings across the whole tenant.

```graphql
query Audience($timeRange: TimeRangeInput!, $topN: Int = 10) {
  analytics {
    usage {
      streaming {
        streamAnalyticsSummariesConnection(timeRange: $timeRange, page: { first: 10 }) {
          edges {
            node {
              streamId
              rangeUniqueViewers
              rangeViewerHours
              rangeViewerSharePercent
            }
          }
        }
        tenantAnalyticsDailyConnection(timeRange: $timeRange, page: { first: 31 }) {
          edges {
            node {
              day
              totalStreams
              totalViews
              uniqueViewers
              egressBytes
            }
          }
        }
        geographicDistribution(timeRange: $timeRange, topN: $topN) {
          totalViewers
          uniqueCountries
          topCountries {
            countryCode
            viewerCount
            percentage
          }
        }
      }
    }
  }
}
```

Omitting `streamId` on `geographicDistribution` aggregates across all of the tenant's streams.

## Tenant usage and billing

`/analytics/usage` and `/account/billing` share the usage surface. Use `usageAggregates` for the rolled-up summary or `usageRecordsConnection` for paginated raw records.

```graphql
query Usage($timeRange: TimeRangeInput!) {
  usageAggregates(timeRange: $timeRange, granularity: "daily") {
    usageType
    periodStart
    periodEnd
    usageValue
  }
  tenantUsage(timeRange: $timeRange) {
    billingPeriod
    usage {
      resourceType
      amount
    }
    totalCost
    currency
  }
}

query DetailedUsage($timeRange: TimeRangeInput, $page: ConnectionInput) {
  usageRecordsConnection(timeRange: $timeRange, page: $page) {
    edges {
      node {
        usageType
        usageValue
        unit
        clusterId
        periodStart
        periodEnd
      }
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

## Network and federation

`/network` and `/infrastructure/federation` show public platform topology and orchestrator vantage points across the federation. Authenticated users also see subscribed or owned clusters with cluster-level KPIs, plus tenant-scoped routing and federation overlays for their own streams.

```graphql
query NetworkStatus {
  networkStatus {
    clusters {
      clusterId
      region
      status
      currentStreams
      currentViewers
      egressMbps
      egressCapacityMbps
    }
    peerConnections {
      sourceCluster
      targetCluster
      connected
    }
  }
  orchestratorVantages {
    orchAddr
    gatewayRegion
    countryCode
    latestLatencyMs
    score
    lastSeen
  }
}
```

## Live event firehose

For dashboards that want the raw event stream (every viewer connect/disconnect, every track change, every storage event), subscribe to the firehose. Be deliberate — this is high-volume.

```graphql
subscription Firehose {
  liveFirehose {
    type
    channel
    timestamp
    streamEvent {
      streamId
      type
      status
    }
    connectionEvent {
      streamId
      sessionId
      connector
    }
    storageEvent {
      streamId
      action
    }
  }
}
```

`channel` is `STREAMS`, `ANALYTICS`, or `SYSTEM`; exactly one of the typed members (`streamEvent`, `viewerMetrics`, `connectionEvent`, `trackListUpdate`, `storageEvent`, `processingEvent`, `routingEvent`, `systemHealthEvent`, and others) is populated per event.

## Agents (MCP)

Agents call analytics through diagnostic tools rather than direct GraphQL — see [agents/mcp](/agents/mcp) for `get_stream_health_summary`, `get_anomaly_report`, `diagnose_buffer_health`, `diagnose_packet_loss`, `diagnose_rebuffering`, and `diagnose_routing`. Each wraps one or more of the queries above with summarization tuned for agent consumption.
