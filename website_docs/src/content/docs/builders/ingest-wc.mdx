## Installation

**NPM:**

```bash
npm install @livepeer-frameworks/streamcrafter-wc
```

```ts
import "@livepeer-frameworks/streamcrafter-wc/define";
```

**CDN (no bundler):**

```html
<!-- unpkg -->
<script src="https://unpkg.com/@livepeer-frameworks/streamcrafter-wc/dist/fw-streamcrafter.iife.js"></script>
<!-- or jsdelivr -->
<script src="https://cdn.jsdelivr.net/npm/@livepeer-frameworks/streamcrafter-wc/dist/fw-streamcrafter.iife.js"></script>
```

Shadow DOM encapsulates all CSS — host page styles won't break controls.

## Drop-in Element

```html
<fw-streamcrafter
  whip-url="%INGEST_URL%/webrtc/your-stream-key"
  initial-profile="broadcast"
></fw-streamcrafter>
```

**Gateway Resolution Mode:**

```html
<fw-streamcrafter
  gateway-url="%GATEWAY_URL%/graphql"
  stream-key="<YOUR_STREAM_KEY>"
  initial-profile="broadcast"
></fw-streamcrafter>
```

Gateway resolution calls the public `resolveIngestEndpoint` GraphQL field from the publisher's
browser, so routing reflects the publisher's location. For backend or encoder-side publishing, use
the dashboard DNS ingest URL or Foghorn's `/ingest/{streamKey}` front door instead.

The element has the same UI as the React and Svelte drop-ins: video preview, Add Camera, Share
Screen and Add Media File, quality selection, the source mixer, the producer panel, the Audio
section, and a connection health pill while live.

## Producer Controls

The producer panel is on by default and appears once the compositor runs: scenes with their
transition, the layers of the active scene, logo and text overlays, and the media files in the mix.
`]` and `[` switch scenes while the studio has focus.

```html
<!-- Simple single-camera studio without the producer panel -->
<fw-streamcrafter whip-url="..." show-producer-panel="false"></fw-streamcrafter>
```

`show-producer-panel` and `enable-compositor` are on unless the attribute says `"false"`. The
context menu's **Copy WHIP URL** copies the full URL, which contains the stream key. **Copy Stream
Info** masks the key.

## Headless Mode

Set `controls="false"` to hide the built-in UI. The element still manages the streaming connection — you provide your own controls:

```html
<fw-streamcrafter
  id="studio"
  whip-url="%INGEST_URL%/webrtc/key"
  controls="false"
></fw-streamcrafter>

<script>
  const studio = document.getElementById("studio");

  document.getElementById("go-live").addEventListener("click", () => {
    studio.pc.startStreaming();
  });

  document.getElementById("add-camera").addEventListener("click", () => {
    studio.pc.startCamera();
  });
</script>
```

### Controller Access

The `.pc` property provides direct access to the underlying `IngestControllerHost`:

```js
const studio = document.querySelector("fw-streamcrafter");

// Read state
studio.pc.getState(); // "idle" | "capturing" | "streaming" | ...
studio.pc.isStreaming(); // boolean
studio.pc.getSources(); // MediaSource[]

// Actions
await studio.pc.startCamera();
await studio.pc.startScreenShare({ audio: true });
await studio.pc.startStreaming();
await studio.pc.stopStreaming();
studio.pc.removeSource("camera-1");
studio.pc.setSourceVolume("camera-1", 0.5);

// Events
studio.pc.on("stateChange", ({ state }) => console.log(state));
```

## Slot-based Composition

With `controls="false"`, the element renders only its default slot, so slotted content replaces the
built-in UI while the element still manages the connection. The studio elements below bind to the
`<fw-streamcrafter>` they sit in, or to the one whose id is in `for`:

```html
<fw-streamcrafter id="studio" whip-url="..." controls="false">
  <div class="my-layout">
    <fw-sc-producer-panel></fw-sc-producer-panel>
    <fw-sc-audio-controls></fw-sc-audio-controls>
    <div class="my-actions">
      <fw-sc-camera-picker></fw-sc-camera-picker>
      <fw-sc-media-button></fw-sc-media-button>
      <button id="go-live">Go Live</button>
    </div>
  </div>
</fw-streamcrafter>

<!-- Outside the studio, bound by id -->
<fw-sc-meter for="studio"></fw-sc-meter>
<fw-sc-connection-health for="studio"></fw-sc-connection-health>
```

A bound element finds a studio that mounts after it and renders again whenever the studio does.

| Element                     | Purpose                                                                        |
| --------------------------- | ------------------------------------------------------------------------------ |
| `<fw-sc-producer-panel>`    | Scenes, layers, overlays and media; renders nothing until the compositor runs  |
| `<fw-sc-overlay-controls>`  | Logo and text overlays of the active scene                                     |
| `<fw-sc-media-controls>`    | Play, pause and loop for media files in the mix                                |
| `<fw-sc-camera-picker>`     | Add Camera, with a list when there is more than one camera or one is live      |
| `<fw-sc-media-button>`      | Add Media File; turned off with the reason where the browser cannot play files |
| `<fw-sc-audio-controls>`    | Noise gate, de-esser, EQ and ducking on the mixed audio                        |
| `<fw-sc-meter>`             | Level meter of the mixed audio                                                 |
| `<fw-sc-connection-health>` | Good, unstable or poor while live, with bitrate, loss and round trip           |

Inside `<fw-streamcrafter>` the Audio section also sets the browser's echo cancellation, noise
suppression and auto gain. A standalone `<fw-sc-audio-controls>` leaves those out.

## Presentational Sub-Components

`<fw-sc-volume>`, `<fw-sc-compositor>`, `<fw-sc-scene-switcher>`, `<fw-sc-layer-list>` and
`<fw-sc-advanced>` are presentational and do not bind to a studio.
`<fw-sc-producer-panel>` wraps the scene switcher and layer list with the
wiring done. To use them on their own, feed them data through JS properties and act on their events
or callback properties:

```html
<fw-streamcrafter id="studio" whip-url="..." controls="false"></fw-streamcrafter>

<fw-sc-volume id="camera-volume"></fw-sc-volume>
<fw-sc-compositor id="layouts"></fw-sc-compositor>

<script type="module">
  const studio = document.getElementById("studio");
  const volume = document.getElementById("camera-volume");
  const layouts = document.getElementById("layouts");

  // The controller is created during the element's first update.
  await studio.updateComplete;
  const sceneManager = () => studio.pc.getController()?.getSceneManager() ?? null;

  function sync() {
    const sources = studio.pc.getSources();
    const scene = sceneManager()?.getActiveScene();
    volume.value = sources[0]?.volume ?? 1;
    layouts.isEnabled = !!sceneManager();
    layouts.isInitialized = !!scene;
    layouts.sources = sources;
    layouts.layers = scene?.layers ?? [];
    layouts.currentLayout = sceneManager()?.getCurrentLayout() ?? null;
  }

  volume.addEventListener("fw-sc-volume-change", (e) => {
    const [source] = studio.pc.getSources();
    if (source) studio.pc.setSourceVolume(source.id, e.detail.value);
  });
  layouts.addEventListener("fw-sc-layout-apply", (e) => {
    sceneManager()?.applyLayout(e.detail.layout);
    sync();
  });
  layouts.addEventListener("fw-sc-cycle-source-order", (e) => {
    sceneManager()?.cycleSourceOrder(e.detail.direction);
    sync();
  });

  for (const event of ["sourceAdded", "sourceRemoved", "sourceUpdated"]) {
    studio.pc.on(event, sync);
  }
  studio.addEventListener("fw-sc-state-change", sync);
</script>
```

`<fw-sc-scene-switcher>` and `<fw-sc-layer-list>` follow the same pattern: set `scenes` /
`activeSceneId` or `layers` / `sources`, and handle actions through callback properties such as
`onSceneSelect`, `onTransitionTo`, `onVisibilityToggle`, `onReorder`, `onTransformEdit` and
`onRemove`.

| Element                  | Purpose                                                    |
| ------------------------ | ---------------------------------------------------------- |
| `<fw-sc-volume>`         | Volume slider with snap to 100%                            |
| `<fw-sc-compositor>`     | Layout and scaling mode selector overlay                   |
| `<fw-sc-scene-switcher>` | Scene tiles with transition controls                       |
| `<fw-sc-layer-list>`     | Layer list with visibility, order, opacity and removal     |
| `<fw-sc-advanced>`       | Dev-mode panel (stats, WebCodecs, encoder, capture format) |

## Attributes Reference

| Attribute                  | Type      | Default       | Description                                                      |
| -------------------------- | --------- | ------------- | ---------------------------------------------------------------- |
| `whip-url`                 | `string`  | —             | Direct WHIP ingest endpoint                                      |
| `gateway-url`              | `string`  | —             | Gateway GraphQL endpoint for resolver-backed ingest environments |
| `stream-key`               | `string`  | —             | Stream key used with `gateway-url`                               |
| `initial-profile`          | `string`  | `"broadcast"` | Quality preset                                                   |
| `auto-start-camera`        | `boolean` | `false`       | Start the camera once an endpoint is known                       |
| `enable-compositor`        | `boolean` | `true`        | Run the compositor; `"false"` turns it off                       |
| `show-producer-panel`      | `boolean` | `true`        | Producer panel while the compositor runs; `"false"` turns it off |
| `show-settings`            | `boolean` | `false`       | Open the quality popup on mount                                  |
| `dev-mode`                 | `boolean` | `false`       | Debug rows in the quality popup and the Advanced panel           |
| `controls`                 | `string`  | `""`          | `"false"` renders only the default slot                          |
| `theme`                    | `string`  | `""`          | Theme preset name (empty uses the built-in default tokens)       |
| `locale`                   | `string`  | `"en"`        | UI language                                                      |
| `class-name`               | `string`  | `""`          | Extra class on the root                                          |
| `compositor-worker-url`    | `string`  | —             | Compositor worker script, when not next to the IIFE bundle       |
| `encoder-worker-url`       | `string`  | —             | Encoder worker script, when not next to the IIFE bundle          |
| `rtc-transform-worker-url` | `string`  | —             | RTC transform worker script, when not next to the IIFE bundle    |
| `debug`                    | `boolean` | `false`       | Enable debug logging                                             |

`compositorConfig`, `resolveWhipUrl`, `onStateChange` and `onError` are JS properties.
`resolveWhipUrl(signal)` returns the destination right before each connection. The `theme`
property also takes an object of token overrides, as in the React and Svelte packages.

## Events

Listen for events on the element:

```js
const studio = document.querySelector("fw-streamcrafter");

studio.addEventListener("fw-sc-state-change", (e) => {
  console.log("State:", e.detail.state);
});
```

## Using with Vue

```vue
<template>
  <fw-streamcrafter :whip-url="whipUrl" initial-profile="broadcast" />
</template>

<script setup>
import "@livepeer-frameworks/streamcrafter-wc/define";

</script>
```
