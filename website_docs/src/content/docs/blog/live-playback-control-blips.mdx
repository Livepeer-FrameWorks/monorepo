Picture a stream in the middle of a broadcast. The encoder is pushing, the edge nodes are serving video, and people are watching. Then the control plane becomes unreachable for a few seconds: a deploy, a database failover, a network partition between regions. Nothing about the media changed. What matters is what happens to the people already watching, and to the people who press play during those seconds.

The rule FrameWorks follows: viewers who are already watching keep watching when the control plane is briefly unreachable. New viewers are admitted from a signed, durable answer the media cluster already holds. If no valid answer exists, the new viewer is refused cleanly. A missing answer is never treated as permission.

## A failure to answer is not an answer

Every new playback request on an edge node goes through a hook: before MistServer starts serving, it asks the FrameWorks edge agent what the requested playback ID resolves to and whether this viewer may have it. The agent asks the cluster's regional load balancer, which holds the policy.

The weak spot was what happened when that question could not be answered. MistServer's hook interface had a single fallback value for "the handler failed", and for playback that fallback was a string that read as a stream name. It could not tell an explicit denial apart from a handler that never replied, and different call sites interpreted the same fallback differently. A control-plane problem could reach the viewer as an arbitrary answer rather than as a failure.

Our MistServer fork now accepts an explicit action for each hook. For playback, a handler that cannot answer produces a denial, and an authoritative rejection produces the same denial. No sentinel value is involved. The edge agent also keeps the hook's definition repaired continuously, because a hook that has gone missing skips the decision entirely instead of failing it.

## Each media cluster holds its own signed answers

Refusing new viewers is still a poor outcome when the media cluster already knows the right answer. So the control plane distributes signed, versioned authority for tenants and media to every cluster that serves them. The cluster verifies each update and commits it to its own database before acknowledging it.

A decision past its soft expiry keeps serving while the cluster requests a refresh. Hard expiry, a signed revocation, or a failed signature check never turns into an allow. Because the answers live in the cluster's database, restarting the regional load balancer does not force a round trip to the central control plane before viewers can be admitted again.

The same signed authority covers ingest ownership, pull sources, processing policy, multistream targets, and restart configuration. Changes and revocations reach each cluster independently. What still needs a live control plane is new management work, such as creating a stream, and new x402 settlement. Media that is already authorized does not.

## Why an earlier viewer's approval is not reused

There is a tempting shortcut: when the regional load balancer is unreachable, remember the last successful answer for a playback ID and hand it to the next viewer who asks for the same one. We do not do this.

An approval for an earlier viewer says nothing about the new viewer's location, about whether the destination that viewer would be sent to still permits them, or about a tenant policy that changed since. Consider a geofenced event, or a signing key that was just revoked. Replaying an earlier yes in those cases would admit exactly the viewers the policy exists to stop. Every new viewer gets a fresh decision from the regional load balancer, based on the signed authority it holds.

## What still fails

Signed local authority protects a media cluster from outages further upstream. Losing every reachable regional load balancer for a cluster is a different failure. New requests then have to reconnect or fail over before they can get a decision, and if no valid answer exists, MistServer applies the explicit denial.

That affects the admission of new viewers only. Playback that is already established is not terminated because the control plane went quiet. The honest boundary is expiry: stored authority serves through its signed validity window, and never beyond it.
