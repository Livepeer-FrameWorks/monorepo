# Platform Module Map

Canonical map of platform modules to their owning microservice. This is curated prose, regenerated by hand during platform audits — it is **not** machine-validated and no tooling enumerates endpoints against it. Last full audit: 2026-07-22 (see `PLAN_PLATFORM_MODULE_MAP.md`).

**Plane terminology** (used consistently across all docs):

- **Control plane** — the Go services (Commodore, Quartermaster, Purser, Bridge, …).
- **Media plane** — MistServer + Livepeer at the edges.
- **Data plane** — event/analytics/attribution/metering (Decklog, Periscope, ClickHouse).
- **Network & trust** — Navigator, Privateer; supports all three planes.

Rows are grouped by plane and sorted by owning service. A row's Plane column may name a second plane the module touches; the row sits in the section of its first-listed plane. Status vocabulary: `shipped` / `partial` / `gap` / `roadmap`. Doc homes: bare names live in `docs/architecture/`, `rfcs/` names in `docs/rfcs/`, `operators/` names in `website_docs/src/content/docs/operators/`. Registry items are slugs in `docs/platform-features.yaml`; `NONE` means the module deliberately has no registry presence (internal glue, or covered only by prose elsewhere).
