# Release v0.3.3

v0.3.3 repairs placement availability and WebRTC startup after the v0.3.2 media-placement rollout, and makes cluster reconciliation report and repair the runtime state it actually finds.

## Upgrade

### Cluster operators

Upgrade from v0.3.2 using the v0.3.3 CLI.

No GitOps or secret changes are required for this release. There are no new manifest fields, provider credentials, or data migrations. `cluster provision` is not required for the normal upgrade.

Use the normal release lifecycle:

```bash
frameworks cluster migrate validate
frameworks cluster release plan --manifest <path> --version v0.3.3
frameworks cluster release apply --manifest <path> --version v0.3.3 --dry-run
frameworks cluster release apply --manifest <path> --version v0.3.3 --yes
frameworks cluster status --manifest <path>
frameworks cluster doctor --manifest <path> --deep
frameworks cluster diff --manifest <path>
```

The normal release applies a Foghorn expand migration before binaries roll and copies any pending managed-stream projection work during postdeploy. Leave the contract migration deferred through the normal observation and rollback window. When rollback to v0.3.2 is no longer required, remove the obsolete outbox with:

```bash
frameworks cluster migrate --manifest <path> --phase contract --to-version v0.3.3 --dry-run
frameworks cluster migrate --manifest <path> --phase contract --to-version v0.3.3 --yes
```

An emergency binary rollback to v0.3.2 remains schema-compatible before that contract migration, but it also restores the broken opaque-cluster-ID projection and should be followed by a v0.3.3 forward fix. Running the contract migration closes the v0.3.2 Foghorn rollback path entirely.

### Edge-only self-hosters

Nothing to do. This release does not change MistServer, the edge protocol, or persistent edge state. Foghorn continues to reconcile edge releases over the existing Helmsman stream.

### Tenants on a managed FrameWorks cluster

No deployment or policy changes are required. Placement policies retain their v0.3.2 behavior, while affected WebRTC sessions and multi-cell placement decisions recover automatically after the platform upgrade.

## Hardened

- **Placement observation budgets.** Every regional cell now receives the complete bounded discovery budget instead of being cut off by nested one-second timers. Decisions remain fail-closed when a cell genuinely cannot return a complete observation.
- **Placement receipt startup.** Foghorn establishes the shared Redis incarnation fence before advertising placement enforcement, avoiding a predictable cold-start rejection window without weakening replay protection.
- **Cluster reconciliation.** Doctor, diff, apply, and release placement paths use authoritative runtime identities, distinguish unknown state from proven drift, retry transient control-plane sessions safely, and inspect the exact running container image.
- **Rendered service drift.** Native-service fingerprints include sandbox and writable-state directives, and service installation repairs stale deployment sentinels.

## Fixes

- Corrected the managed-stream active-cluster outbox to store opaque cluster IDs such as `media-eu-1` instead of requiring UUIDs.
- Fixed Mist WebRTC startup so signaling subscribes for the SDP answer before sending the offer and applies play or hold only after the answer is installed.
- Removed a request for the nonexistent public `/webrtc.js` helper, which production correctly rejected as HTML rather than JavaScript.
- Kept non-autoplay WebRTC startup neutral until the viewer explicitly plays, allowing initial metadata and tracks to arrive without a synthetic hold deadlock.

## Build / Infra

- Increased the Yugabyte schema-contract harness allowance for real-engine convergence under constrained CI hosts. The production migration behavior is unchanged.
